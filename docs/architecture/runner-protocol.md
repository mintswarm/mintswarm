# Runner protocol

A runner talks to the control plane through one gRPC service in the package `mintswarm.runner.v1`, defined in `api/proto/mintswarm/runner/v1/`: `runner.proto` (the service and its unary and blob calls), `connect.proto` (the `Connect` stream's envelopes and messages), `events.proto` (runner events), `steps.proto` (step kinds) and `common.proto` (`Secret`). Rust for these protos is generated by `crates/proto`; it prints every `Secret` as `Secret(<redacted>)`, so no message that holds one prints its value. `crates/proto` also gives every message its proto3 JSON mapping through `mintswarm_proto::json`, built from the descriptor set that its `build.rs` writes; it writes each `Secret` as `{"value":"<redacted>"}` and never reads JSON that holds a `Secret`. This document describes the protocol as the protos define it. The reasoning, defaults and timings are in the [runner protocol design on #156](https://github.com/mintswarm/mintswarm/issues/156/artifacts/3), whose sections the proto comments cite as "design §n". Enum values are written in lowercase without their prefix: `draining` stands for `CLAIM_REFUSAL_REASON_DRAINING`.

## Service

`RunnerService` is the service a runner calls on the plane. Every sha256 in it is the lowercase hex digest of the bytes it names.

| RPC | Shape | Authentication | Errors | Purpose |
| --- | --- | --- | --- | --- |
| `Register` | unary: `RegisterRequest` → `RegisterResponse` | none; the request carries the one-time registration token | `UNAUTHENTICATED` for an unknown, expired, used-up or revoked token; `FAILED_PRECONDITION` with reason `repository_mismatch` or `upgrade_required` | registers a new runner with its Ed25519 public key, repository, host and protocol minor version (design §9.1) |
| `Authenticate` | unary: `AuthenticateRequest` → `AuthenticateResponse` | none; the request carries a client assertion signed with the runner key | `UNAUTHENTICATED` when the assertion fails the plane's checks | exchanges the assertion for an access token, with RFC 7523's names (design §9.2) |
| `Connect` | bidirectional stream: `ConnectRequest` ⇄ `ConnectResponse` | `authorization: Bearer <access token>` | `FAILED_PRECONDITION` when the first message is not `Hello` or `HelloAck` | the session stream that carries all live traffic (design §5) |
| `StatBlobs` | unary: `StatBlobsRequest` → `StatBlobsResponse` | access token | none stated | returns which of the given blobs the plane lacks (design §8.2) |
| `PutBlob` | client stream: `PutBlobRequest` → `PutBlobResponse` | access token | `DATA_LOSS` when the bytes do not hash to the header's sha256; `RESOURCE_EXHAUSTED` when the blob is over `max_blob_bytes` | uploads one blob (design §8.2) |
| `GetBlob` | server stream: `GetBlobRequest` → `GetBlobResponse` | access token | none stated | downloads one blob that belongs to the fenced attempt's job (design §8.2) |

`RegisterResponse` gives the runner its `runner_id`, its `project`, the `default_tags` the plane applied and the `audience` its client assertions use. `AuthenticateResponse` carries the opaque `access_token` and its `expires_at`. The registration token, the client assertion and the access token are all `Secret` messages.

## Envelope

Everything on the `Connect` stream travels in one of two envelopes, each a message with a single `body` oneof:

- `ConnectRequest`, sent by the runner;
- `ConnectResponse`, sent by the plane.

The envelope rules, as the proto comments state them (design §5.3):

- `Hello` is the first runner message on every stream, and `HelloAck` the first plane message.
- Anything else sent first closes the stream with `FAILED_PRECONDITION`.
- A receiver ignores an envelope case it does not know and counts it, never treating it as fatal.

## Messages and direction

| Sender | Case | Message | What it does |
| --- | --- | --- | --- |
| runner | `hello` | `Hello` | opens the session; always the first message |
| runner | `claim` | `Claim` | an idle worker asks for work |
| runner | `cancel_claim` | `CancelClaim` | withdraws a claim |
| runner | `heartbeat` | `Heartbeat` | the runner's periodic state; renews its leases |
| runner | `events` | `EventBatch` | outbox items, in contiguous `seq` order |
| runner | `reauthenticate` | `Reauthenticate` | presents a refreshed access token |
| runner | `capabilities` | `CapabilitiesUpdate` | the runner's full set of probe results, sent when they change |
| runner | `metrics` | `HostMetrics` | the runner's periodic host metrics |
| runner | `goodbye` | `Goodbye` | the runner's last message before it closes the stream |
| plane | `hello_ack` | `HelloAck` | answers `Hello`; always the first message |
| plane | `claim_result` | `ClaimResult` | answers a claim |
| plane | `heartbeat_ack` | `HeartbeatAck` | answers a heartbeat with the state of each lease |

| plane | `resend` | `Resend` | asks the runner to resend its outbox from a `seq` |

## Session

`Hello` (design §6.1) describes the runner and what it holds:

- its `runner_version`, its `protocol_minor`, the optional `features` it supports and every `StepKind` it executes (`step_kinds`);
- its outbox position: `outbox_epoch`, a random 128-bit id, with `first_unacked_seq` and `last_seq`;
- its host, `Harness` list, probe results (`ProbeResult`, whose schema is contract C7), tags, harness account and `workers_total`;
- the repository it serves (`HelloRepository`: `remote` and the `default_branch_head` of its trusted store). The plane checks `remote` against the project's repository at every `Hello` and reads the default-branch head itself, so `default_branch_head` only shows how far behind the runner's store is;
- its `RunnerMode`: `worker` claims work, `observer` never does;
- every attempt it believes it runs, as `HeldAttempt` (`attempt_id`, `lease_epoch`, `phase`).

`HelloAck` (design §6.2) has one of two results:

- `HelloRejected`: the plane refuses the session and closes the stream. Its `HelloRejectionStatus` is `upgrade_required`, `revoked` or `repository_mismatch`, with a `detail`. For `upgrade_required` it also sets `min_protocol_minor` and `plane_version`. A superseded stream is never refused here; it gets a `GoAway`.
- `HelloAccepted`: the plane accepts the session. It carries:
  - the stream's `session_id`, the plane's `protocol_minor` and the negotiated `features`;
  - `acked_seq`, the last `seq` acknowledged for the runner's `outbox_epoch`;
  - `SessionLimits`: `max_message_bytes`, `max_blob_bytes`, `max_in_flight_events`, `max_in_flight_bytes` and `claim_wait_seconds`;
  - `SessionTimings`: `heartbeat_seconds`, `lease_seconds` and `metrics_seconds`, so a plane tunes them without a runner release;
  - every attempt the plane believes the runner holds, as `PlaneHeldAttempt` with a `PlaneAttemptState` of `assigned` or `started` (design §6.3; the message that carries an assignment is not yet defined, see [Not yet defined](#not-yet-defined));
  - the `pending_directives` sent before and not yet receipted.

During the session:

- The runner refreshes its access token with `Reauthenticate`, and the plane answers `Reauthenticated` with the new `expires_at` (design §9.4).
- The runner sends `CapabilitiesUpdate` with every probe result and harness whenever they change (design §5.2, §7.3), and `HostMetrics` periodically (design §5.2, §7.5).
- The runner ends with `Goodbye`; its only `GoodbyeReason` is `drained`, sent once it has finished draining and its outbox is acknowledged.
- The plane ends with `GoAway`, whose `GoAwayReason` is `superseded` (a newer stream authenticated for the same runner), `token_expired` or `shutdown`. Its `reconnect_after`, when set, overrides the runner's reconnect backoff.

## Work

Claims (design §7.1):

- An idle worker sends `Claim` with a `request_id` unique within the stream and its `worker_id`. `CancelClaim` withdraws it by `request_id`; if the plane has already assigned, the assignment still arrives.
- The plane answers each claim exactly once with `ClaimResult`. Its result is `NoWork` when nothing is eligible within `claim_wait_seconds`, after which the worker claims again, or `ClaimRefused` with a `ClaimRefusalReason` of `draining`, `throttled`, `observer` or `paused`.

Heartbeats and leases (design §7.3):

- `Heartbeat` carries the runner's `RunnerState` (`online`, `draining` or `paused`), its free and total workers, a `LoadSummary`, `throttled_until`, every `HeldAttempt` it holds, its outbox head `last_seq` and a `capabilities_digest`.
- A heartbeat renews the lease of every listed attempt whose fence is current; there is no other renewal.
- `HeartbeatAck` answers with one `LeaseState` per listed attempt, the `plane_time`, and `resend_capabilities` when the digest differs from the last update the plane stored. A `LeaseState` either gives the renewed `expires_at`, by the plane's clock, or is `Revoked`, in which case the runner aborts the attempt.

Directives (design §7.6):

- A `Directive` has a `directive_id`, stable across resends, and one `kind`:
  - `cancel` (`Cancel`) stops an attempt;
  - `interrupt` (`Interrupt`) interrupts an attempt's harness session, with an optional message for the session after it;
  - `deliver` (`Deliver`) delivers an operator's message to an attempt;
  - `drain` (`Drain`) makes the runner stop claiming, finish or cancel its attempts by an optional `deadline`, then send `Goodbye` with reason `drained`;
  - `upgrade` (`UpgradeRequired`) says the plane refuses the runner's protocol minor version from now on, with `min_protocol_minor`; the runner drains and stops reconnecting until it is upgraded.
- The attempt-scoped kinds name the attempt by `attempt_id` and `lease_epoch`.
- The plane delivers a directive at least once, until the runner's `DirectiveReceipt` event for it arrives; the runner deduplicates by `directive_id`. The receipt's `DirectiveDisposition` says what the runner did with it.

## Events and acknowledgement

Events (design §8.1, `events.proto`):

- The runner sends its outbox as `EventBatch` messages of `RunnerEvent`s with contiguous, ascending `seq` values and no gaps.
- `seq` is the runner's single outbox counter: one counter per runner.
- A `RunnerEvent` carries its `seq`, the time `at` which the runner recorded it, and for job events the `job_id`, `attempt_id` and `lease_epoch`. These three are empty or zero for runner-level events.
- Its `body` is one of:
  - `AttemptStarted`;
  - `AttemptStartFailed`, with an `AttemptStartFailedReason` of `duplicate` or `unsupported`;
  - `AttemptOutcome`, with an `AttemptOutcomeKind`, a `reason` and an optional branch `head`; the plane stores a kind it does not know as `failed`;
  - `Usage`, with token counts, cost and account limits;
  - `Progress`, sent only under the `progress_events` feature;
  - `Warning`;
  - `RecordPut` and `ArtefactPut`, which name their bytes by sha256; the bytes travel through the blob calls;
  - `DirectiveReceipt`;
  - `StageResult`, the stage's result block with its `Question` objects.

Acknowledgement (design §8.3):

- `Ack` carries a `seq`: every item up to and including it is durably stored, or durably recorded as fenced or ignored.
- `Resend` asks the runner to resend its outbox from a `seq`, after a gap.
- `NeedBlobs` names an item's `seq` and the sha256 of each blob it names that the plane lacks. The plane acknowledges the item once they arrive.
- On a new stream, `Hello` reports the runner's `first_unacked_seq` and `last_seq`, and `HelloAccepted` the plane's `acked_seq` for the runner's `outbox_epoch`.

Blobs (design §8.2):

- `StatBlobs` returns the sha256 of each given blob the plane lacks.
- `PutBlob` uploads one blob. Its first message is a `PutBlobHeader` (sha256, size, media type and fence), every one after it a chunk of at most 1 MiB. The plane checks the bytes against the header's sha256.
- `GetBlob` downloads one blob of the fenced attempt's job. The first message is a `GetBlobHeader`, every one after it a chunk of at most 1 MiB, and the runner checks the sha256 before using the bytes.

## Fencing

The fence is the design's `(attempt_id, lease_epoch)` pair (design §7.4), written inline as the two fields `attempt_id` and `lease_epoch`. It is on:

- every job event (`RunnerEvent`);
- the blob calls (`PutBlobHeader`, `GetBlobRequest`);
- the attempts each side holds (`HeldAttempt`, `PlaneHeldAttempt`), the leases (`LeaseState`) and the attempt-scoped directives.

The plane drops a fenced event whose fence is stale. A stale fence does not fail `PutBlob`: the blob is still stored, since it is content-addressed.

## Versioning and features

- The package is `mintswarm.runner.v1`. A breaking change gets a new version directory beside `v1/` (see [repository layout](repository-layout.md)).
- Inside `v1`, a runner reports its `protocol_minor` in `RegisterRequest` and `Hello`, and the plane its own in `HelloAccepted`. A plane that refuses a runner's minor version says so with `HelloRejected` or the `UpgradeRequired` directive, both carrying `min_protocol_minor`, and `Register` refuses a runner that is too old with `FAILED_PRECONDITION` and reason `upgrade_required`.
- `features` are strings. The runner lists those it supports in `Hello`, and `HelloAccepted` returns the negotiated set: those both sides support.
- `StepKind` is an open enum. The plane never dispatches a kind outside `Hello.step_kinds`, and a runner that receives a kind it does not know answers with `AttemptStartFailed` and reason `unsupported`.
- The `proto-lint` gate runs `buf lint`. `buf breaking` is not a gate until the runner–plane exchange is live (#483); its category in `api/proto/buf.yaml` is `WIRE_JSON`.
- Until the exchange is live, a field or message that goes is deleted outright, without `reserved`: no deployed peer has seen it. Once it is live, a deletion reserves the number and the name.
- The feature list and the support window for minor versions are in design §10.

## Not yet defined

Assignment and credential messages are not yet defined. In the protos:

- field 6 of `ConnectRequest` and of `ConnectResponse` is unused, and not `reserved`;
- field 2 of the `ClaimResult` result is unused, and not `reserved`.

The protocol has no message that hands an attempt to a runner, and no `Connect` case that requests or delivers a credential for an attempt.
