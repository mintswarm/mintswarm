# Authentication

Logging in to the control plane, its sessions and the GitHub link are defined as contracts in two proto packages. This document describes those contracts as the protos define them; nothing behind them is implemented yet. The reasoning is in the [authentication design on #634](https://github.com/mintswarm/mintswarm/issues/634/artifacts/3), whose sections the proto comments cite as "§n". Enum values are written in lowercase without their prefix: `open_on_github` stands for `AVAILABILITY_STATE_OPEN_ON_GITHUB`.

## Packages

| Package | File | Holds |
| --- | --- | --- |
| `mintswarm.common.v1` | `api/proto/mintswarm/common/v1/secret.proto` | `Secret`, which `mintswarm.runner.v1` and `mintswarm.auth.v1` share |
| `mintswarm.auth.v1` | `api/proto/mintswarm/auth/v1/availability.proto` | `ActionAvailability`, `ActionKind`, `AvailabilityState` and `AvailabilityReason`; it imports nothing, so Control API messages can embed them without the service |
| `mintswarm.auth.v1` | `api/proto/mintswarm/auth/v1/auth.proto` | `AuthService`, its messages, `ClientKind` and `LinkState` |

Rust for both packages is generated by `crates/proto`, as `mintswarm_proto::common::v1` and `mintswarm_proto::auth::v1`, with the tonic `AuthServiceClient` and `AuthServiceServer`. Adding RPCs, fields or enum values is a minor change; a breaking change gets a `v2/` package.

## Secret

`Secret { value }` holds every secret value the protocols carry: the runner's registration token, client assertion and access tokens, and the session token, device-flow handle, static login token and loopback authorisation code of `mintswarm.auth.v1`. `crates/proto` prints every `Secret` as `Secret(<redacted>)`, so no message that holds one prints its value. Its proto3 JSON, through `mintswarm_proto::json`, writes each `Secret` as `{"value":"<redacted>"}`, and JSON that holds a `Secret` is never read.

## Availability

`ActionAvailability { action, state, url, reason }` is the one source of what a person may do with an action on an item (§5). It is meant to be embedded in Control API item messages; `watch.v1` does not carry it.

- `AvailabilityState`: `act` (the plane acts as the person), `confirm` (a fresh sign-in is needed first), `open_on_github` (the person acts on GitHub, at `url`) and `hidden`.
- `AvailabilityReason`, set when the state is not `act`: `no_link`, `link_broken`, `insufficient_role`, `not_trusted`, `app_permission_missing`, `endpoint_refuses_user_token`, `non_interactive_session` and `acting_disabled`.

## AuthService

`AuthService` serves the CLI and the console MCP over gRPC. A session is presented as `authorization: Bearer <token>`. Every RPC may return `UNAVAILABLE` when the server is shutting down or its database is unreachable. Every RPC except `ListProviders`, `BeginLogin`, `PollDeviceLogin` and `CompleteLogin` returns `UNAUTHENTICATED` for an unknown, expired, revoked or no longer admitted session (§8.1).

Only the RPCs that return no `Secret` and start no browser flow carry a `google.api.http` annotation, for the HTTP transcoder; the others are gRPC only. Browsers start flows at the edge (§7.1), so `BeginLogin`, `CompleteLogin` and `BeginLink` refuse a `client_kind` of `web` or unspecified.

| RPC | Request → reply | HTTP | Errors besides `UNAVAILABLE` and `UNAUTHENTICATED` |
| --- | --- | --- | --- |
| `ListProviders` | `{}` → `{ providers }`, each `Provider { id, display_name }` | `GET /v1/auth/providers` | none; it needs no session, so it never returns `UNAUTHENTICATED` |
| `BeginLogin` | `{ provider, client_kind, host }` → `start`: `redirect` (`Redirect { url }`), `device` (`DeviceChallenge`) or `credentials` (`CredentialsExpected`) | none | `INVALID_ARGUMENT` for an unknown provider, or for a `client_kind` of `web` or unspecified |
| `PollDeviceLogin` | `{ handle }` → `result`: `pending` (`DevicePending`) or `session` (`SessionGrant`) | none | `NOT_FOUND` for an unknown or expired handle; `PERMISSION_DENIED` for a denied authorisation or a failed admission |
| `CompleteLogin` | `{ provider, client_kind, host, credentials }`, where `credentials` is `token` (`Secret`) or `redirect` (`LoopbackRedirect`) → `{ session }` (`SessionGrant`) | none | `INVALID_ARGUMENT` for an unknown provider, the wrong credentials case, or a `client_kind` of `web` or unspecified (§7.1); `UNAUTHENTICATED` for refused credentials; `PERMISSION_DENIED` for a failed admission |
| `GetSession` | `{}` → `{ session }` (`Session`) | `GET /v1/auth/session` | none |
| `ListSessions` | `{}` → `{ sessions }`, the caller's own | `GET /v1/auth/sessions` | none |
| `RevokeSession` | `{ session_id }` → `{}` | `POST /v1/auth/sessions/{session_id}/revoke` | `NOT_FOUND` for an unknown session or one not the caller's own |
| `Logout` | `{}` → `{}` | none | none |
| `BeginLink` | `{ client_kind, host }` → `start`: `redirect` (`Redirect`) or `device` (`DeviceChallenge`) | none | `INVALID_ARGUMENT` for a `client_kind` of `web` or unspecified; `FAILED_PRECONDITION` for a non-interactive session |
| `PollDeviceLink` | `{ handle }` → `result`: `pending` (`DevicePending`) or `link` (`Link`) | none | `NOT_FOUND` for an unknown or expired handle; `PERMISSION_DENIED` for a denied authorisation or a different GitHub user id (§7.3); `ALREADY_EXISTS` for a GitHub account linked to another identity |
| `CompleteLink` | `{ redirect }` (`LoopbackRedirect`) → `{ link }` (`Link`) | none | `PERMISSION_DENIED`, `ALREADY_EXISTS` and `FAILED_PRECONDITION`, as for `PollDeviceLink` and `BeginLink` |
| `Unlink` | `{}` → `{}` | `DELETE /v1/auth/link` | none |
| `GetLink` | `{}` → `{ link }` (`Link`), unset when there is no link | `GET /v1/auth/link` | none |

The CLI and the console MCP link through the `device` case of `BeginLink` (B4). Its `redirect` case, completed with `CompleteLink`, mirrors the login loopback form of `BeginLogin` and `CompleteLogin`.

## Messages

- `DeviceChallenge { user_code, verification_url, interval, expires_at, handle }`: `handle` is a `Secret`, held by the client that polls with it.
- `LoopbackRedirect { code, state }`: what the browser brought back to the client's loopback address; `code` is a `Secret`.
- `SessionGrant { session_id, token, expires_at, idle_limit }`: the session token as a `Secret`, returned once, with its absolute expiry and idle limit. `PollDeviceLogin` and `CompleteLogin` return it.
- `Session { id, provider, client_kind, host, created_at, last_seen_at, expires_at, idle_limit, interactive, current }`: `host` is the requesting host the login requests name, `interactive` is false for token-provider sessions, and `current` marks the caller's own session.
- `Link { state, login, github_user_id }`: a GitHub link's state and login, never its tokens.
